# Лабораторная работа № 3. Обработка исключений, работа с файлами и сериализация

**Автор:** Карманов Александр Евгеньевич  
**Группа:** КБ-251

Приложение читает список геометрических фигур из текстового файла, выводит их площади и периметры, строит цилиндр со случайным основанием из списка и сохраняет список в бинарный файл средствами сериализации Java.

## Структура проекта

```text
src/
├─ app/
│  ├─ Main.java              — сценарий приложения (задание № 6)
│  └─ Checks.java            — воспроизводимые проверки из чек-листа
├─ geometry2d/
│  ├─ Figure.java            — интерфейс: area(), perimeter(); extends Serializable
│  ├─ Circle.java
│  └─ Rectangle.java
├─ geometry3d/
│  └─ Cylinder.java          — основание типа Figure, высота double, volume()
├─ exceptions/
│  ├─ InvalidFigureParameterException.java  — непроверяемое, некорректный параметр
│  ├─ FigureStorageException.java           — проверяемое, неверное содержимое файла
│  └─ FigureFormatException.java            — проверяемое, ошибка в строке текстового файла
└─ storage/
   ├─ FigureStorage.java       — интерфейс read / write
   ├─ TextFigureStorage.java   — текстовый формат (java.nio, UTF-8)
   └─ BinaryFigureStorage.java — сериализация (ObjectOutputStream / ObjectInputStream)
data/                          — примеры входных файлов
results/                       — сохранённый вывод проверок и запусков
```

## Сборка и запуск

Требуется JDK 21+ (проверено на JDK 21, работа рассчитана на JDK 25 LTS).

```bash
# компиляция (из корня проекта)
javac -encoding UTF-8 -d out src/*/*.java

# запуск приложения: входной текстовый файл, выходной бинарный файл, высота цилиндра
java -cp out app.Main data/figures.txt figures.bin 5

# без аргументов пути и высота запрашиваются с консоли
java -cp out app.Main

# прогон всех проверок из чек-листа
java -cp out app.Checks
```

> В Windows, если в консоли «кракозябры» вместо русского текста, выполните `chcp 65001` перед запуском или добавьте `-Dstdout.encoding=UTF-8`.

В OpenIDE / IntelliJ IDEA: пометить `src` как Sources Root, запустить `app.Main` (аргументы задать в Run Configuration → Program arguments) или `app.Checks`.

## Текстовый формат фигур

Одна фигура — одна строка, поля разделены точкой с запятой `;`:

| Фигура | Строка | Пример |
|---|---|---|
| Круг | `CIRCLE;радиус` | `CIRCLE;1.5` |
| Прямоугольник | `RECTANGLE;ширина;высота` | `RECTANGLE;2;3` |

- Кодировка — UTF-8 (BOM, который добавляет Блокнот Windows, пропускается).
- Тип фигуры не чувствителен к регистру, пробелы вокруг полей игнорируются (`rectangle ; 2 ; 3` — корректная строка).
- Десятичный разделитель — точка (`1.5`).
- Пустые строки и строки, начинающиеся с `#`, пропускаются (комментарии).
- При записи числа выводятся через `Double.toString`, поэтому после повторного чтения значения совпадают точно.

## Поведение при ошибках чтения

**Загрузка отклоняется целиком.** При первой некорректной строке `TextFigureStorage.read` выбрасывает `FigureFormatException` с номером строки и причиной; фигуры, прочитанные из предыдущих строк, отбрасываются — вызывающий код получает либо весь корректный список, либо исключение. `Main` сообщает об ошибке, выводит причину и завершается с кодом 1, бинарный файл не записывается.

Некорректной считается строка с неизвестным типом фигуры, неверным количеством параметров, нечисловым параметром или недопустимым значением (≤ 0, `NaN`, `Infinity`). В двух последних случаях исходное исключение (`NumberFormatException` или `InvalidFigureParameterException`) сохраняется как причина (`getCause()`).

## Исключения: выбор базовых классов

| Исключение | Базовый класс | Когда выбрасывается | Что делает вызывающий код |
|---|---|---|---|
| `InvalidFigureParameterException` | `IllegalArgumentException` (непроверяемое) | Конструктор фигуры получил размер ≤ 0, `NaN`, бесконечность или `null` вместо основания цилиндра | Это ошибка аргумента, а не внешней среды; обязательный `catch` не нужен. `TextFigureStorage` перехватывает её и оборачивает в `FigureFormatException` с номером строки; `Main` перехватывает при создании цилиндра и сообщает, что цилиндр не создан |
| `FigureStorageException` | `Exception` (проверяемое) | Содержимое файла не является списком фигур: повреждённый бинарный файл, объект другого типа, `ClassNotFoundException` (обёрнут с сохранением причины) | Зависит от внешних данных, поэтому компилятор заставляет обработать. `Main` сообщает об ошибке и завершает работу |
| `FigureFormatException` | `FigureStorageException` | Ошибка в конкретной строке текстового файла; хранит `getLineNumber()` | `Main` выводит номер строки и причину, загрузка отклоняется |

Контракт интерфейса `FigureStorage`:

```java
List<Figure> read(Path path) throws IOException, FigureStorageException;
void write(Path path, List<Figure> figures) throws IOException, FigureStorageException;
```

`IOException` — файловые ошибки (нет файла → `NoSuchFileException`, путь является каталогом, нет прав), `FigureStorageException` — ошибки содержимого.

Дополнительно: стандартная десериализация не вызывает конструктор, поэтому в `Circle`, `Rectangle` и `Cylinder` определён `readObject`, который повторяет проверки параметров. Подделанный бинарный файл с отрицательным радиусом будет отклонён (`InvalidObjectException` → `FigureStorageException`).
